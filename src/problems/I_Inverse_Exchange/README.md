# I. Inverse Exchange

## Условие (кратко)
Сетка `n × m` из 0/1. Операция: выбрать путь `P` из левого верхнего угла в правый нижний
(вниз/вправо) и путь `Q` из правого верхнего в левый нижний (вниз/влево) и инвертировать
все клетки их объединения. Нужно не более чем за `2nm` операций минимизировать число единиц.

## Инвариант
Любые `P` и `Q` проходят через все **четыре угла**, поэтому каждая операция инвертирует
все 4 угла сразу. Значит, попарные XOR угловых клеток не меняются.

Перебор на маленьких сетках показывает, что ранг множества операций (над GF(2)) равен
ровно `nm − 3`. Других ограничений нет: любую неугловую клетку можно перевернуть
отдельно, а углы — только все вместе.

**Ответ:** все неугловые клетки обнуляются, в углах остаётся `min(w, 4 − w)` единиц,
где `w` — число единиц в углах.

## Конструкция
1. Если `w ≥ 3`, делаем одну операцию `O0` (`P = R…RD…D`, `Q = L…LD…D`): она переворачивает
   углы и ещё какие-то клетки, которые просто учитываем.
2. Каждую оставшуюся неугловую единицу `x` гасим **гаджетом из двух операций**
   `(P1, Q)` и `(P2, Q)`:
   - `P1` и `P2` отличаются одним «поворотом»: один проходит через `x`, другой — через
     соседнюю по диагонали клетку `y`;
   - `Q` проходит через `y`, но не через `x`.

   Объединения отличаются ровно в клетке `x`.
3. Для разных положений `x` (внутри, у верхнего/нижнего, левого/правого края) гаджет
   строится в «удобной» позиции и отражается по строкам или столбцам. Отражение
   превращает пути типа `P` в пути типа `Q` и наоборот.

Итого не больше `1 + 2(nm − 4) ≤ 2nm` операций.

## Сложность
`O(nm · (n + m))` — размер вывода.

# B. Binary Search Trees

## Условие (кратко)
Дано дерево из `n` вершин, степень каждой вершины ≤ 3. Ключи `1..n` расставляются по
вершинам всеми `n!` способами. Вершина `r` — «хороший корень», если, подвесив дерево за `r`
и назвав детей левыми/правыми, можно получить бинарное дерево поиска.
Нужно найти сумму количества хороших корней по всем расстановкам (по модулю 998244353).

## Идея
Меняем порядок суммирования: для каждого корня `r` считаем, сколько расстановок ключей
делают его хорошим.

- Если `deg(r) = 3`, у корня было бы 3 ребёнка — так нельзя, вклад 0.
- Иначе зафиксируем, кто из детей каждой вершины левый, а кто правый. Тогда в BST ключи
  определяются **однозначно**: это порядок обхода in-order (левое поддерево, вершина,
  правое поддерево).
- Разные назначения «левый/правый» дают разные расстановки ключей.

Сколько всего назначений? Каждая вершина, у которой есть дети, даёт множитель 2:
- 2 ребёнка — какой из них левый (2 способа);
- 1 ребёнок — он левый или правый (2 способа);
- лист — 1 способ.

Детей нет только у листьев исходного дерева (вершин степени 1), кроме случая, когда
такая вершина сама является корнем. Поэтому:

```
f(r) = 2^(n - leaves + [deg(r) == 1]),  если deg(r) ≤ 2
f(r) = 0,                                если deg(r) = 3
ответ = Σ f(r)
```

## Проверка на примере
Путь `1-2-3`: листьев 2.
- `r = 1` и `r = 3`: 2^(3 − 2 + 1) = 4;
- `r = 2`: 2^(3 − 2) = 2.

Сумма 4 + 2 + 4 = 10 — совпадает с ответом.

## Сложность
`O(n)` на тест.

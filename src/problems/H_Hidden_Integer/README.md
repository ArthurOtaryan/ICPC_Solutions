# H. Hidden Integer (интерактивная)

## Условие (кратко)
Загадано `1 ≤ n ≤ 10⁹`. Запрос `? x` возвращает `(n mod x) mod 2`. Нужно найти `n`
не более чем за 30 запросов.

## Наблюдения
- Для **чётного** `x` ответ всегда равен `n mod 2`: вычитание кратных чётного числа
  чётность не меняет. Значит, полезен только один такой запрос: `? 2` → `p = n mod 2`.
- Для **нечётного** `x` при `n < 2x`:
  - `n < x` → `n mod x = n`, ответ `p`;
  - `x ≤ n < 2x` → `n mod x = n − x`, ответ `p xor 1`.

  То есть ответ = `p xor [n ≥ x]`, и это обычный вопрос бинпоиска «`n ≥ x`?».

## Алгоритм
1. Узнаём `p`.
2. Кандидаты — числа чётности `p` на `[1, 10⁹]`: их 5·10⁸ ≤ 2²⁹.
3. Бинпоиск: делим кандидатов пополам, порог `x` — нечётное число на стыке половин
   (первый кандидат верхней половины, если `p = 1`, или на 1 меньше, если `p = 0`).
   Нижняя половина берётся размера `⌈k/2⌉`, тогда всегда `2x > максимум кандидатов`,
   и условие `n < 2x` выполнено.
4. 29 шагов бинпоиска + 1 запрос = **30 запросов**.

## Не забыть
После каждого запроса нужен `flush`.
